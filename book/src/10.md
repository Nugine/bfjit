# 10. 实现 LLVM 后端

本章实现 `src/bfjit_llvm.rs`。它与 dynasm 版本并列存在：dynasm 版本展示如何手写机器码，LLVM 版本展示如何构造 LLVM IR 并交给 JIT 执行。

## 模块结构

LLVM 后端需要 `Context`、`Module`、`Builder`、`ExecutionEngine` 等类型。虚拟机结构与 dynasm 版本保持一致，仍然保存机器码执行所需对象、内存、输入流和输出流。

```rust,noplaypen
{{#include ../../src/bfjit_llvm.rs:1:26}}
```

`ExecutionEngine` 持有 JIT 生成的代码。`Context` 的生命周期需要长于它；为了避免在教程里引入自引用结构，本实现把 `Context` 泄漏为 `'static`。命令行程序通常只创建一个虚拟机，这个取舍可以让核心逻辑更清晰。

## 运行时回调

Brainfuck 的 `,` 和 `.` 需要访问 Rust 的输入输出流。LLVM IR 中先声明外部函数，JIT 初始化后再把这些声明映射到真实 Rust 函数地址。

这些回调沿用 dynasm 版本的错误传递方式：成功返回空指针，失败返回堆上的 `VMError` 指针。

```rust,noplaypen
{{#include ../../src/bfjit_llvm.rs:28:64}}
```

## 初始化与执行

`new` 方法读取文件、编译到 `BfIR`、可选优化，然后调用 LLVM 编译器。执行时把 JIT 函数地址转换为函数指针，传入虚拟机指针和内存边界。

```rust,noplaypen
{{#include ../../src/bfjit_llvm.rs:66:121}}
```

生成出的函数签名是：

```rust,noplaypen
unsafe extern "C" fn(
    this: *mut BfLlvmVM<'_>,
    memory_start: *mut u8,
    memory_end: *const u8,
) -> *mut VMError
```

返回空指针表示正常结束；返回非空指针表示编译出的代码遇到了 IO 错误或指针越界。

## 创建 LLVM 模块和 JIT

`compile` 是 LLVM 后端的入口。它完成以下工作：

1. 创建 `Context`、`Module` 和 `Builder`。
2. 定义 `bfjit_main` 函数。
3. 声明 `getbyte`、`putbyte` 和 `overflow_error` 三个外部函数。
4. 调用 `build_function` 生成函数体。
5. 验证模块。
6. 创建 JIT execution engine。
7. 把外部函数声明映射到 Rust 函数地址。
8. 查询 `bfjit_main` 的机器码地址。

```rust,noplaypen
{{#include ../../src/bfjit_llvm.rs:124:175}}
```

LLVM 使用模块保存函数和全局符号；builder 负责在当前基本块末尾追加指令。和 dynasm 直接“写汇编”不同，LLVM 的基本单位是类型化 IR。

## 生成函数体

函数入口首先创建一个局部槽位 `ptr`，保存 Brainfuck 当前数据指针。这样后续指令只需要读写这个槽位，不必手工分配寄存器，也不用为循环手写 phi 节点。

```rust,noplaypen
{{#include ../../src/bfjit_llvm.rs:177:283}}
```

循环处理仍然使用栈。遇到 `Jz` 时创建循环体和循环出口两个基本块；遇到 `Jnz` 时弹出对应基本块并生成回边。

## 指针移动和边界检查

dynasm 版本使用 `add/sub` 后检查进位和数组边界。LLVM 版本把指针转成整数，执行加减，再用无符号比较判断是否溢出或越界。

```rust,noplaypen
{{#include ../../src/bfjit_llvm.rs:285:361}}
```

如果检查失败，控制流跳到统一的 `overflow` 基本块，调用 `overflow_error` 生成 `RuntimeError::PointerOverflow`。

## 字节读写和 IO

单元格加减是普通的 `load`、整数运算和 `store`。LLVM 的 `i8` 加减默认允许回绕，正好匹配 Brainfuck 字节语义。
